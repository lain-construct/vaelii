Settle Dependency Graph

Every structure the engine keeps between writes, what each one is computed from, and the write events that retire it, drawn from the derived-state register (caches/derived-state). Nothing here is drawn by hand: a register change is a new export and a regeneration. Click a box to see what it reads, what reads it and which events retire it; click an event to see every structure it retires and how.

The graph

Events on the left, then the stores and the network labels (M1) as sources, then every row grouped by its letter. A read edge runs from the structure read to its reader and takes the colour of the reader's coarsest retirement code under an ordinary write (the lifecycle events that rebuild or wipe every structure are left out of that choice).

Features and removability

The features the settle graph has named, each with its removability and the register rows that hold its state (scripts/derived-state-features.edn). A feature's namespaces are the owners of its rows plus the owners of the rows outside it that read them.

    The register

    One line per row, in the register's order. The count columns appear when the export carries them: held is the number of entries a row held when the export was taken, and any other count is a counter the register reports.

    Event × structure

    Each cell is the code with which the event retires the row; with a reading that carries one, the number under it is the entries that event retired there.

    The write events

    The closed event set, caches/events: each event, the vars it passes through, and how many rows it retires.
